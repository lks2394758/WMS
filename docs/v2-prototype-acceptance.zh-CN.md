# WMS v2 展示原型自动化验收

日期：2026-10-20（America/Vancouver）。后端由 Claude 开发，前端、独立复核和测试由 Codex 完成。

## 结论与边界

B0 至 B5 的本地 SQLite 展示原型功能已通过本轮自动化验收。保留旧 v1 和旧数据库；不迁移旧数据，不修改旧账号。没有安装新框架、数据库服务器或系统组件，没有提交或部署。本轮没有常驻启动演示服务。

这不是生产上线验收，也不等于用户已完成人工业务验收。SQL Server/PostgreSQL、跨进程/多服务器并发、TLS/IIS、备份恢复运维和真实打印机/扫描枪仍需另行验证。

## 验收覆盖

- 独立新库初始化、会话重启保留、单有效会话、当前身份权限及账号变更撤销。
- 商品、可选图片、单位/分类、四级库位/货架生成、账号和设置；精确字符串 ID/数量。
- 入出移调、包装换算、多行原子回滚、防重、SQLite 并发库存检查、实物状态及历史编码。
- 盘点冻结/盲盘/不可变结果、取消复盘恢复、确认调整、序列差异调查、明确结案。
- 首页统计与本人/全仓动态、提醒生命周期和触发快照、操作历史与筛选。
- 框架拒绝的 400/415/401/403/429/413 安全失败日志；业务/登录失败不重复记账；审计写入失败不改变原拒绝响应。

审计限制：代理或服务器在应用流水线之前拒绝的请求无法补记；读取请求的拒绝不记业务操作日志；审计存储故障时不能保证落库。5 秒取消令牌为协作式限制，不是同步 SQLite 等待的硬截止。客户端中断只有在请求仍能走完拒绝处理时才可补记，不能保证所有断线都有业务日志。

## 后续人工展示

先在本机安全配置中设置 `V2:Seed:Password`（至少 8 位，不写入仓库，不发送给 AI）；已有账号不会因此重置。旧版 `start-demo.ps1` 启动的是 v1，不能把它当作 v2 启动器。

在仓库根目录的终端启动新版后端：

```powershell
$env:ASPNETCORE_ENVIRONMENT = 'Development'
$env:ASPNETCORE_URLS = 'http://127.0.0.1:5057'
$env:V2__Enabled = 'true'
dotnet run --project src/Wms.Api --no-launch-profile
```

在前端目录的另一终端启动：

```powershell
$env:WMS_V2_API_BASE_URL = 'http://127.0.0.1:5057'
npm start
```

入口为 `http://localhost:4173/v2/`；首次手工启动会使用配置的新库 `App_Data/wms-v2-demo.db`，不是本轮测试临时库。启动前确认端口未被其他服务占用，不自动终止已有进程。人工验收后再决定是否需要专门的启动器、展示数据或后续部署。
