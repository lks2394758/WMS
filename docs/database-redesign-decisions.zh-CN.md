# WMS 数据库重设计：逐项确认记录

更新日期：2026-10-19（America/Vancouver）。

状态：业务设计及逻辑结构已整理，剩余业务缺口按用户授权采用下文建议定稿；尚未实施到代码、API 或现有 SQLite 数据库。本文记录本聊天中用户逐项确认及授权定稿的决定；后续明确修改的决定覆盖较早选择。第 17 节补充设计约束，不代表已生成或验证物理建库脚本。

## 1. 范围和首页

- 单仓库展示原型，继续以易部署、免费和未来可更换数据库为目标。
- 新结构实施时保留旧数据库，另建新库并重新初始化演示数据；不覆盖旧库，不迁移旧商品、库存或历史。本次仅确认方案，尚未创建新库。
- 首页包含库存汇总、最近操作、异常提醒、商品搜索、其他页面导航。
- 汇总显示所有未删除商品的 SKU 数，包括零库存商品；不将不同单位的数量相加，也不显示全仓库存总数量。
- 商品列表显示各商品的库存数量和单位。
- 商品名称、SKU、条码均可搜索。结果显示名称、SKU、基础单位、总库存，展开查看各库位数量、容量、占用率、警告。
- 最近操作默认全仓，可切换为仅自己，显示谁、何时、以什么身份进行了什么操作，以及成功或失败及原因。
- 独立操作历史页支持时间、操作人、商品、库位、操作类型、成功/失败筛选和明细查看。
- 本阶段不提供数据导出。
- 商品条码、库位、实物序列号均支持标签打印，打印时选择一维条码或二维码；图形类型不会改变标识值或给商品增加第二个条码编号。

## 2. 商品、单位和分类

- 内部主键采用自增数字 ID；SKU、条码、库位编码是独立业务字段。
- 商品名称可重复，SKU 和条码必须唯一。
- SKU、商品条码、实物序列号均不区分大小写，例如 ABC123 和 abc123 视为同一编码；当前和历史保留编码的防重校验采用一致规则。
- SKU 默认自动生成，也允许人工填写。
- 自动 SKU 采用 SKU-000001、SKU-000002 等可读编号，持续递增且不复用；无论自动或人工填写，均检查唯一性。
- 每个商品必须且只能有一个条码，可录入/扫描现有码，也可生成内部码。
- 自动内部商品条码采用 BC-000001、BC-000002 等编号；打印一维条码或二维码时使用同一个条码值，已有厂商条码仍可直接录入。
- 商品创建后允许修改 SKU 和当前条码，但必须全仓库存为零，且没有未完成盘点或待核查任务。旧编码保留历史并永久禁止复用；旧条码不继续充当当前有效条码，保证每个商品只有一个当前条码。完整字段设计需覆盖历史编码占用校验，不能只检查当前列的唯一性。
- 旧 SKU、旧条码分别以 JSON 历史编码数组保存在商品表，不独立建立编码登记表。应用在写事务中统一检查所有商品的当前与历史编码，包括已归档商品，并按不区分大小写的规则防重；仅对当前字段建立唯一索引不足以覆盖历史占用要求。
- 商品分类支持多层，每个商品可关联多个分类。筛选上级分类包含其子分类。
- 分类可选，无分类时显示为“未分类”。
- 每件商品可选上传最多一张图片。
- 商品图片直接存入数据库，作为商品表中的可空图片内容及必要格式信息，不保存外部文件路径，不另建图片表；数据库备份包含图片数据。
- 默认基础单位为“件”、数量为整数。可在入库创建商品时选择自定义基础单位并开启小数。
- 单位由统一列表管理并允许新增；每种商品可单独设置小数位数。
- 商品小数位数允许设置为 0～6 位：0 表示整数，1～6 表示该商品允许的最大小数位数；启用序列号的商品固定为 0。
- 后续入库、出库、库存显示、库位容量统一使用商品的基础单位和精度。
- 商品在所有库位库存均为零后，才可修改基础单位和小数规则。历史仍显示当时的单位和数值。
- 每次入库分别填写包装单位、包装数量和换算比例，不预存固定包装换算表。
- 换算结果超出允许精度时拒绝提交，不自动舍入。
- 商品管理页可建商品，入库时也可建商品并完成库位容量配置。

### 删除商品

- 所有库位库存为零，且该商品没有未完成盘点或待调查事项时才允许删除。
- 删除采用保留资料的归档标记；从商品列表、搜索和新入库选择中移除。
- 原 SKU、条码继续占用，不允许其他商品复用。
- 历史流水保留当时的商品名称、SKU、单位等快照。
- 删除时清除零库存库位保留的该商品关联和容量，结束相关低位提醒，保留异常历史，库位回到完全空闲状态。

## 3. 仓库位置、库存和容量

- 位置层级：库区 → 货架 → 层 → 格，格为最小独立库位。
- 不为四级位置分别建表；使用一张库位表，列中保存库区、货架、层、格及完整编码。
- 库位编码自动生成，例如 A-B-C-04。
- 全仓配置新建货架的默认层数和每层格数，创建货架时按当时的规格生成库位；修改配置只影响新建货架，已有货架保留原结构。因此不同时期创建的货架可以有不同结构，这覆盖了早期“所有货架始终同规格”的选择。
- 库位页有列表和货架示意图，可切换、点击查看详情。
- 同一时间一个库位只存一种商品；同商品可分散在多个库位。
- 库位表同时保存当前商品、数量、容量和可选阈值。不另建库存余额表或商品库位容量配置表。
- 空库位重新入库时必须填写本次容量；有库存的同商品补货沿用当前容量。
- 空库位重新入库配置容量时，高低位阈值恢复全仓默认值，本次允许单独修改，不沿用该库位上次的覆盖值。
- 这覆盖了早期“预先保存库位＋商品容量并复用”的方案：不再保留历史容量配置用于自动复用。
- 清空后保留上次商品和容量，显示 0% 和低位警告；仍允许换商品。重新入库时重新填写容量。
- 占用率为当前数量除以当前容量，数量与容量使用同一基础单位。
- 默认低于 20% 为低位，高于 80% 为高位；库位可覆盖全仓默认阈值。
- 允许超容量入库；超过 100% 显示超容量警告，而非阻止入库。
- 库存不能为负；盘点冻结时禁止入库、出库、移库和独立库存调整。
- 删除库位要求库存为零，且没有未完成盘点或待核查任务；删除后从库位列表和货架图移除，历史流水、位置快照和异常历史保留，采用保留关联证据的归档方式。
- 允许修改已有库位所属的库区、货架、层和格，但要求无库存、无未完成盘点或待核查任务；系统自动重新生成编码并留操作日志，不改写历史位置快照。

## 4. 入库、出库、移库和调整

### 入库

- 支持多行，各行指定商品、目标库位、包装数量及换算比例。
- 同一商品可以分多行入不同库位。
- 提交即增加库存，不设草稿；整单成功或整单失败。
- 来源名称自由填写，不建立供应商/来源资料表。
- 系统推荐库位，用户可修改：优先同商品且有余量的库位，再推荐可用于本次入库的空库位。
- 空库位推荐和提交规则应以本次配置容量为准；不能继续依赖已取消的历史商品库位容量表。

### 出库

- 支持多行，提交即扣库存，无草稿，整单原子提交。
- 人工选择来源库位和数量，同商品可从多个库位出库。
- 使用商品基础单位；去向名称/说明自由填写，不建客户/部门资料表。

### 移库

- 多行指定商品、来源库位、目标库位和数量，提交即转移，整单成功或失败。
- 总量不变；目标库位仍遵守单商品和空位容量配置规则。

### 调整和纠错

- 保留独立调整功能；普通商品填增加/减少量，并预览调整后数量。
- 原因必填，不能调整为负数。
- 序列号商品增加时录入或生成实物序列号，减少时指定具体实物；数量由所选序列号个数计算。
- 成功入库、出库、移库不提供原记录修改或一键撤销，通过新的反向操作或调整纠正。
- 流水、明细、相关操作证据不可修改或删除；纠错追加记录。

## 5. 实物序列号

- 不管理批次和有效期。
- 部分商品可启用逐件序列号，全系统唯一，不同商品之间也不能重复。
- 此类商品按实物个数管理，不支持小数。
- 商品的序列号追踪开关仅可在全仓库存为零，且无未完成盘点或待核查任务时修改；已有实物序列号和流水历史保留，不随开关变化删除或改写。
- 序列号可手工输入/扫描，也可由系统批量生成。
- 实物在库时不能重复入库；已出库实物可用原序列号回库，沿用实物 ID，保留连续历史。
- 出库/移库/调整通过具体实物关联流水，普通商品不需要序列号关联。

## 6. 盘点和差异

- 每次盘点一个库位。
- 采用盲盘：提交前不显示账面数量，提交后查看数量和差异。
- 开始后冻结库位；一般盘点流程完成或取消后解除冻结。
- 先保存不可更改的盘点结果，再单独确认调整；盘点人可自行确认，无须另一人审批。
- 无差异盘点提交后也不自动完成，必须手动点击确认完成才结束任务并解除库位冻结；不产生库存调整流水。
- 有差异且确认调整时，原因必填，并留下不可修改的人员、角色、时间、位置、商品、账面/实盘数量、差异和调整结果。
- 盘点任务维护流程状态；已提交的盘点结果保存事实，不随任务状态变化而修改。
- 已提交结果但尚未调整库存时，若数量填错，在原任务下追加一份复盘结果，旧结果完整保留，不覆盖；一项任务可有多份有序结果，后续确认仅针对最新有效结果。

### 序列号商品的特殊规则

- 只比较数量，不要求逐件扫描，也不核对现场序列号清单。
- 数量差异仅记为“待核查”，不直接修改库存数量或序列号状态。
- 结束本次盘点并解除冻结，待核查差异继续在首页提醒。
- 后续通过关联实际库存调整，或填写“无需调整”的核查结论及原因结案。
- 核查处理以追加日志留痕，不能重写原盘点结果。
- 因核查期间库位已解冻，后续调整必须验证当时的实时库存/实物；不能把旧差额盲目应用到已变化的库存。
- 解冻后发起复盘时，重新冻结库位，并以复盘开始时的实时库存形成新的账面快照；原盘点结果不变。复盘仍采用盲盘，账面数量在结果提交前不展示。

## 7. 异常和操作日志

- 异常记录表包含低位、高位、超容量和盘点待核查差异等。
- 首页显示未结束异常，恢复正常/核查结案后结束提醒并保留历史。
- 相同持续异常不重复创建；恢复后再次异常应新增一次异常记录。
- 不设人工“已知晓”。
- 保存触发时的数量、容量、阈值和关联对象快照，避免资料变更重写历史。
- 统一操作日志用于首页最近操作及独立历史页，覆盖成功和失败、库存操作、商品资料变更、盘点核查和角色切换。
- 日志记录账号、姓名/身份快照、时间、类型、对象、摘要、结果、失败原因和关联流水/任务 ID；不写密码或登录令牌。
- 日志只追加；失败日志不能随失败库存事务的回滚一起消失。

## 8. 账号、角色和会话

- 账号由管理员创建和维护，不开放注册。管理员管理姓名、角色、启用/停用、重置密码。
- 普通用户不能自行修改密码，密码仅管理员重置。
- 账号和角色合并为一张账号表；Roles 为 JSON 数组。
- 四个固定角色：管理员、仓库主管、收货员、发货员。不另建角色表、账号角色关联表或四个布尔开关。
- 角色数组仅允许固定合法值、无重复、至少一个；姓名/用户名等约束在完整字段设计中明确。
- 管理员负责全部业务、账号和系统设置；主管负责商品、库位和全部库存业务；收货员查询/入库；发货员查询/出库。
- 例外已确认：收货员可在入库时新增商品、单位和本次商品库位容量，但不能修改或删除已有资料。
- 一账号多角色，登录后选择本次身份，权限按当前身份生效。
- 不退出即可切换到已分配的其他身份，记录切换日志及每次操作的身份快照。
- 独立登录会话表保存账号、当前角色、令牌摘要、登录/过期/退出或撤销时间。
- 刷新页面/重开浏览器在有效期内保持登录，主动退出或过期后重新登录。
- 默认登录有效期 8 小时，由管理员在全仓设置中配置。
- 同一账号不允许多个设备/浏览器同时登录，新登录使旧会话失效；角色切换仍在当前会话内进行。已过期/已退出会话保留记录，不因新登录删除历史。

## 9. 技术辅助数据

- 不独立建立防重复提交表。
- 成功库存流水主表保存请求编号和内容摘要，以账号和请求编号的唯一约束配合事务防止重复过账。
- 相同请求返回既有不可更改的流水结果；相同编号而内容不同应拒绝。
- 防重代码必须使用持久流水事实，不能仅依赖进程内存。
- 盘点提交等不直接产生库存流水的请求，还需在实施设计中明确其自然唯一约束/状态转换重试行为；不能假设流水防重自动覆盖全部端点。
- 公共设置集中一张表：新建货架默认层数、每层格数、默认高低位阈值、登录有效期；货架规格配置修改不追溯调整已有货架。
- 编号计数器按第 17.3 节集中到 SystemSettings 的技术字段，不追加独立编号表；具体数据库写入实现仍需验证。

## 12. 逐表确认的字段清单

### 商品表 Products（已确认）

| 业务字段 | 规则 |
| --- | --- |
| ID | 自增数字主键 |
| SKU | 当前商品编码，必填、唯一、不区分大小写；支持自动生成或人工填写 |
| 商品名称 | 必填，允许重名 |
| 条码 | 必须且只有一个当前条码，唯一、不区分大小写 |
| 单位 ID | 关联统一单位表 |
| 小数位数 | 0～6；启用序列号的商品固定为 0 |
| 序列号追踪开关 | 决定是否逐件管理 |
| 图片 | 可空，图片内容直接存数据库，格式信息作为配套技术字段 |

## 13. 跨表规则逐项确认

### 账号变更与会话撤销（已确认）

管理员停用账号、重置密码或修改账号角色后，立即撤销该账号现有登录会话。仍获准使用的账号须重新登录，以重新验证账号状态和角色权限，旧会话不得继续沿用原权限。

### 默认告警阈值变更（已确认）

修改全仓默认高低位阈值后，立即应用于未单独设置对应阈值的现有库位，重新判断异常并更新相关提醒。库位单独设置的阈值不受影响；低位和高位分别判断是否使用默认值。

### 登录有效时长变更（已确认）

管理员修改登录有效时长，只影响之后新建立的登录会话。现有会话保留原定到期时间，不因设置变化而缩短或延长；账号变更等主动撤销规则仍然生效。

### 盘点解冻后的差异处理（已确认）

序列号商品盘点发现数量差异，结束盘点并解冻库位后，调查期间库存可以继续变化。调查结论不得直接套用旧盘点差额修改库存，须核实当前实物情况，通过新的库存调整处理，并关联原盘点结果。原始盘点记录始终保留，不得改写。

### 待调查库位更换商品（已确认）

库位存在未解决的盘点差异待调查事项时，即使当前库存已经清零，也不得换放另一种商品，须先解决待调查事项。调查期间已解冻的库位仍可正常出入库原商品，其他库存及权限校验继续适用。

### 待调查期间再次盘点（已确认）

同一个库位已有未解决的盘点调查时，允许再次盘点，但作为原任务的新一轮复盘，不另开重复任务。每轮重新冻结库位，记录当时的实时账面数量，保留各轮提交结果。新结果不会自动关闭旧差异，仍须明确记录处理结论。原任务的再次盘点遵守既定状态流转，冻结期间禁止库存变动。

### 实物序列号纠错（已确认）

实物序列号录入后不得直接修改或重新分配给另一件实物。录入错误时，仅管理员或主管可通过专门的纠错操作处理，保留原值、新值、纠错原因及操作人。纠错不改变实物 ID，不改写历史流水中的序列号快照；旧号占用及保存方式按下列已确认规则执行。

### 纠错后的旧序列号（已确认）

纠错后的旧序列号永久保留给原实物，不得分配给其他实物。查询旧号码仍能找到原实物，并提示已更正后的当前序列号。当前及历史序列号均遵守全系统、不区分大小写的唯一占用规则，使用下列历史序列号数组保存。

### 历史序列号保存方式（已确认）

在 SerializedItems 表增加历史序列号数组，保存该实物纠错前的号码，不另建表。纠错原因、操作人和时间保存在操作日志中。当前号码与所有历史号码均不得被其他实物占用；写入时须统一检查当前及历史号码，不能只依赖当前序列号列的唯一索引。

### 旧序列号的扫描与操作（已确认）

扫描已经更正的旧序列号时，允许查询原实物，但不得直接提交出入库等库存操作。系统须提示该号码已更正及当前新号码，要求使用新号码确认操作，避免旧标签继续用于库存操作。历史记录保留当时的原始号码快照。

## 14. 汇总后的逻辑结构

本节串联已确认的 16 张表；不新增业务表。第 12 节为字段清单，第 13 节为跨表行为。逻辑结构不等同于可直接执行的建库脚本。

| 业务链路 | 表间关系及职责 |
| --- | --- |
| 商品资料 | Products 关联一个 Units；通过 ProductCategories 关联多个 Categories；Categories 自关联形成分类树 |
| 当前库存 | Bins 关联当前或上次商品；商品全仓库存由有效库位数量汇总，不另外保存一份商品总库存 |
| 库存历史 | InventoryTransactions 一对多关联 InventoryTransactionLines；明细关联商品及来源/目标库位，并保留操作时快照 |
| 逐件追踪 | SerializedItems 关联所属商品及当前库位；TransactionLineItems 将流水明细与具体实物关联，保留当时序列号 |
| 盘点 | CountTasks 关联一个库位，一对多关联 CountResults；Bins 的冻结任务引用与盘点任务须保持一致 |
| 差异处置 | 库存调整流水可关联具体 CountResults；无需调整的结论由 ActivityLogs 留痕；Alerts 展示待调查状态，不能作为库存事实 |
| 操作历史 | ActivityLogs 关联相关业务对象，保存人员身份快照和成功/失败结果；不是第二份库存流水 |
| 登录权限 | Users 一对多保留 LoginSessions 历史，但同一账号最多一个有效会话；当前权限由有效会话所选角色决定 |
| 全仓设置 | SystemSettings 保存单仓默认值；库位告警默认值动态适用，货架结构默认值及登录时长按已确认的各自生效规则处理 |

### 已确定的事实与变化边界

- 当前事实：库位数量、实物位置和在库状态；只能随经过验证的库存操作事务一起变化。
- 历史证据：成功流水、明细、实物关联、已提交盘点结果和操作日志，只追加，不改写。
- 流程状态：盘点任务、提醒状态、登录会话可以按规则更新；更新不能覆盖历史证据。
- 业务资料：商品、分类、单位及库位的位置资料按权限修改；不得以资料修改代替库存操作。
- 归档不是级联删除：商品或库位归档后，历史引用及快照仍须保留。

## 17. 按授权采用的设计定稿

本节为用户授权后采用的设计决定，不是已经实现的功能。不新增第 17 张业务表，不改变单仓库、SQLite 展示、保留旧库的范围。

### 17.1 盘点状态、复盘和取消

| 操作 | 任务状态与冻结变化 |
| --- | --- |
| 首次开始 | 进入盘点中；建立第 1 轮快照并冻结库位 |
| 提交本轮数量 | 新增不可变结果，进入待确认；继续冻结 |
| 确认完成 | 普通商品按规则确认调整或无差异完成；序列号差异转调查。进入已完成并解冻 |
| 结果未处理、仍冻结时复盘 | 待确认转盘点中；建立新轮次快照，旧结果保留，持续冻结 |
| 调查期间重新复盘 | 已完成转盘点中；重新冻结，读取当时库存生成新快照 |
| 首轮未提交时取消 | 进入已取消并解冻；记录取消原因、人员和时间 |
| 从待确认发起的复盘未提交时取消 | 恢复待确认及上次有效结果；结束本轮冻结后原待确认冻结仍须保留，不得对外开放库存操作 |
| 从已完成发起的复盘未提交时取消 | 恢复已完成及上次完成时间，解冻；旧结果和未解决调查继续保留 |

- 通用的“取消后解冻”指不再需要原任务冻结的情况；恢复待确认时例外，必须继续冻结，避免尚待确认的普通商品差额失去安全前提。
- 任务首次开始时间不覆盖；本轮开始时间随轮次保存。重新开启已完成任务时，当前完成时间清空；再次完成填新完成时间。
- 在任务中保存本轮开始前的流程状态、上一完成时间和本轮轮次，支持取消恢复。历次开始、取消和完成事件保存在追加日志，不能只保留最后一个时间。
- 已提交本轮结果不能取消该结果，只能在尚未处理库存时复盘或按规则处理。已过账的调整不能通过重开任务撤销。
- 取消的轮次同样占用轮次编号，后续轮次继续递增；日志保留取消轮次的账面快照，不伪造实盘结果。
- 普通商品确认调整时，由专用确认流程在同一事务中验证任务与最新结果、调整库存、保存流水、完成任务并解除本任务冻结；通用库存接口不能绕过冻结。
- 任一时刻，同库位只允许一个冻结任务。盘点提交、确认和复盘均比较任务版本及轮次，拒绝过期页面的操作。

### 17.2 旧实物回库与商品计量变更

- 保留已确认的零库存时修改单位、精度或序列号开关能力；存在未完成盘点或待调查事项时，三者均不得修改。
- 回库按商品当前规则验证，不沿用旧流水的计量配置，不自动将旧数量当作新单位数量。
- 当前启用序列号时，一件实物计 1 个当前基础单位，精度必须为 0；单位应表达独立个体，如件、台、箱，而不能借单位变更将一件旧实物解释为不同数量。
- 旧实物以原 ID、当前有效序列号回库；旧号码只能查询，纠错规则继续适用。
- 当前已关闭追踪时，拒绝以旧序列号身份直接回库，提示须满足原有零库存及无未决任务条件后重新启用；不得悄悄将旧实物当作无追踪商品入库。
- 若商品已变成按重量、长度等不同计量含义管理，不强行沿用旧实物记录。应使用独立商品资料及显式库存操作处理，保留原实物历史，不改其所属商品。
- 商品已归档时不可直接回库；本阶段不新增自动恢复或合并实物功能。

### 17.3 编码与编号

- 用户名去除首尾空白后不区分大小写，规范化用户名唯一；姓名不是唯一标识。
- SKU、条码及实物序列号拒绝空值、控制字符和首尾空白；以统一规范化规则检查当前和历史占用。保留输入大小写用于显示。
- 实物自动序列号采用 SN-000001 形式，持续递增；位数超过六位时自然扩展，不回绕、不复用。
- 自动编号使用在同一写事务内访问的 SystemSettings 技术计数器字段，不增加编号表；覆盖 SKU、内部条码、实物序列号、流水和任务编号。人工号码与自动号码冲突时自动分配跳过已占用值。
- 流水编号采用 TX-000001，任务编号采用 CT-000001。编号允许有缺号，不承诺连续无断号；成功编号不得重复。
- 库位完整编码统一生成，位置标识不允许包含分隔符以免编码歧义；同一位置以规范化坐标防重。
- 归档库位编码永久保留，不通过新建另一条记录复用；需要重新启用原位置时，应设计显式恢复原记录流程，而不是悄悄新建。恢复功能不计入本阶段必做范围。
- 库位重编码后，旧编码记入 Bins 的历史编码数组并永久保留；历史位置查询使用快照。历史编码不用于当前库存操作，避免旧标签指向新位置。

### 17.4 分类和单位维护

- 分类有子分类或商品关联时禁止删除，提示先处理关联；不级联删除商品或子树。无引用分类可删除并留操作日志。
- 商品多分类关联可独立增删，记录日志；归档商品的分类引用同样计入删除检查。
- 分类可改名或换上级，但须校验同级名称唯一及无循环；历史资料变更日志保留原路径。
- 单位被任何商品引用时禁止删除，包括归档商品；系统预置“件”不可删除。未使用的自定义单位可删除并留痕。
- 单位改名只用于名称纠正，不得借此改变计量含义，例如不能将“公斤”改成“克”来代替换算。不同计量含义必须新增单位，再按商品零库存等规则切换。
- 单位、分类名称去首尾空白后进行不区分大小写的唯一性校验；单位全局唯一，分类同级唯一。
- 改名影响当前页面显示，但不改写已提交流水、盘点及告警快照。

### 17.5 容量告警与调查结案

- 同一库位同时只显示一种容量状态，优先级：超容量 > 高位 > 低位 > 正常；无商品、无容量的完全空闲库位不触发容量提醒。
- 阈值使用严格比较：占比低于低阈值触发低位，高于高阈值触发高位，超过 100% 触发超容量；等于边界不触发对应越界提醒。
- 状态切换时关闭旧容量提醒并新建新类型提醒；持续同类型异常不重复建记录，也不覆盖最初触发快照。当前数量另读库位事实。
- 修改默认阈值前须检查所有受影响库位的有效高低值。若与单独覆盖值冲突，整次设置修改拒绝并列出冲突库位，不悄悄删除覆盖值或提交一半。
- 保留上次商品和有效容量的零库存库位继续按 0% 判断低位；商品归档清理库位后关闭提醒。
- 每个待调查任务最多一个未解决调查提醒，关联首次未结案差异结果；后续轮次通过任务及结果链查询，新增结果不自动关闭或覆盖原提醒证据。
- 结案须明确覆盖该任务尚未处置的差异结果，在不可变操作日志中列出结果 ID、处理结论、原因、处理人和时间。需要库存调整时另关联实际成功调整流水。
- 不要求新流水数量机械等于原差额，而要证明对当前实物的处理；无需调整也必须填调查结论。只有明确处置完全部未决差异，才关闭调查提醒。
- 任务新一轮复盘为零差异，仅作为调查证据，不自动结案；结案和冻结中的复盘不能交错执行。

### 17.6 字段边界与精确数量

| 项目 | 设计约束 |
| --- | --- |
| 主键 | 正的 64 位自增整数；外键同类型；已使用主键不复用 |
| SKU、商品条码、实物序列号 | 1～128 个字符；历史数组每项同样验证 |
| 商品名称 | 1～128 个字符 |
| 用户名、姓名 | 分别 1～64、1～100 个字符；用户名不允许空白及控制字符 |
| 单位、分类名称 | 分别 1～32、1～64 个字符 |
| 库区、货架、层、格标识 | 各 1～16 个字符；完整库位编码最多 128 个字符 |
| 来源/去向 | 可空，最多 200 个字符 |
| 原因、备注、调查结论 | 最多 2000 个字符；业务要求必填时不能只有空白 |
| 图片 | 可空，最多 2 MiB；仅 PNG/JPEG，服务端验证实际格式；不接受 SVG 或仅信任文件扩展名 |
| 商品精度 | 0～6；序列号商品为 0 |
| 单个数量绝对值上限 | 999999999999.999999；还须满足商品自己的精度；普通操作数量大于零，调整为非零有符号差额 |
| 包装数量、换算比例 | 均大于零、最多六位小数，单值不超过上述上限；精确乘法后校验目标商品精度和上限，溢出或需舍入则拒绝 |
| 容量 | 必须大于零，使用商品基础单位及精度，遵守数量上限 |
| 高低阈值 | 百分数最多两位小数，0 ≤ 低位 < 高位 ≤ 100；覆盖与默认组合后的有效值也须满足顺序 |
| 新货架默认规格 | 层数和每层格数各 1～100；单次创建最多 10000 格 |
| 登录时长 | 1～168 小时，整数，默认 8 |

- 精确数量统一按六位小数缩放为整数存储；SQLite 使用 64 位 INTEGER，不使用 REAL 保存库存。商品精度只控制允许输入和展示的位数，不改变已有数量的缩放含义。
- 未来 SQL Server/PostgreSQL 使用相同缩放整数约定，以免更换引擎改变数值含义；中间乘法、差值和汇总使用足够范围的精确数值并进行溢出检查。
- 商品跨库位汇总不截断到单库位上限；如超出输出或计算范围，明确报错，不回绕、不静默舍入。
- API v2 的 ID 及精确十进制数量使用字符串表示，避免浏览器大整数及小数精度损失；API 文档必须写清单位、范围和精度。页面只格式化展示，最终校验和运算由服务端完成。
- 对上传图片、批量行数和请求体还需在接口配置中设置资源保护上限，不将服务器内存耗尽视为普通校验手段。
- 不在此次设计中擅自重置现有演示账号密码；新库凭证通过安全配置提供，不写入文档、日志或演示初始化脚本。
- 修改商品单位或精度时，所有零库存库位保留的该商品旧容量及阈值配置一并清空并留痕，关闭对应旧容量提醒；保留商品引用但不展示无效占比，后续入库按新单位重新配置容量，历史快照不变。

### 17.7 不增表的辅助字段与持久化规则

- Products：按已有约定保存编码历史数组，增加创建/修改时间及并发版本。Bins 补充历史编码数组、创建/修改时间和并发版本。
- CountTasks：补充当前轮次、当前快照、复盘前状态、复盘前完成时间、取消时间及原因、并发版本；每轮开始/取消/完成事件写不可变日志。
- CountResults：商品 ID、库位 ID 等对象引用独立保存，商品名、SKU、条码、单位、精度、库位编码为不可变快照；同任务轮次唯一。
- Alerts：保留触发时结构化快照，调查提醒的结案证据通过关联任务及日志查询；解决说明不能替代实际库存调整流水。
- ActivityLogs：结构化关联对象数组保存对象类型和 ID，支持多个商品/库位及相关任务、结果、流水；改变前后内容另存结构化字段。成功登录失败前尚未验证身份时账号可空，角色不得伪造，登录标识须脱敏。
- SystemSettings：补充各类编号计数器和并发版本，属于技术字段，不增加业务设置页面上的任意配置项。
- LoginSessions：凭证哈希唯一；账号停用、角色变更、密码重置及新登录撤销旧会话须与账号/会话写入一致，后续请求验证数据库中的有效状态。
- 所有持久字段必须有明确外键或结构化引用校验；不可变证据不允许级联删除。数组中的历史码及日志对象引用由服务层在事务中校验。
- 数据库写入保护禁止更新或删除成功流水、明细、序列号关联、已提交盘点结果和操作日志；可变资料采用乐观并发版本，避免过期页面覆盖新资料。
- 非流水操作以目标状态、任务版本及自然唯一键保证重试语义：相同轮次重复提交相同结果返回原结果，不同结果拒绝；重复确认不二次调整；纠错重试不得重复追加旧号或日志。
